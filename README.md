# arecia

CTF와 웹 보안 연구를 기록하는 arecia의 블로그입니다. 글, 프로젝트, 소개와 수상 내역은 Notion에서 편집하고, GitHub Actions가 Jekyll로 빌드해 GitHub Pages에 배포합니다.

[홈](https://areciah.github.io/) · [전체 글](https://areciah.github.io/posts/) · [프로젝트](https://areciah.github.io/projects/) · [소개](https://areciah.github.io/cv/)

## Notion에서 발행하기

[블로그 데이터베이스](https://app.notion.com/p/4233839a3ab981dd8d75fa22d8e9acc9)에서 페이지를 만들거나 글 양식을 복제한 뒤 본문을 작성합니다. **상태** 속성으로 발행 위치를 정합니다.

| 상태 | 사이트에 반영되는 내용 |
| --- | --- |
| `발행` | 전체 글 목록과 글 상세 페이지. 최근 글 3편은 홈에도 표시됩니다. |
| `발행 (비밀번호)` | 목록에는 제목·날짜·잠금 표시가 나오고, 상세 페이지에서 글별 비밀번호를 입력하면 본문이 열립니다. |
| `프로젝트 공개` | 프로젝트 목록과 독립된 상세 페이지. 홈에는 최대 2개가 표시됩니다. |
| `소개 반영` | 소개 페이지와 홈의 수상 내역. 소개 원본 한 페이지에만 지정합니다. |

초안·양식·비공개 등 다른 상태는 발행 대상에서 제외됩니다. 이미 발행한 페이지도 상태를 초안으로 되돌리면 다음 배포가 성공했을 때 사이트에서 내려갑니다.

### 글

- **제목과 요약**은 글 목록에 쓰입니다. **발행일**(날짜)을 비워 두면 Notion 페이지 생성일을 사용합니다.
- **카테고리**(선택 또는 다중 선택)와 **태그**(다중 선택)에 새 값을 추가하면 해당 글을 발행한 뒤 전체 글의 필터에 나타납니다. 독자는 최신순·오래된순으로 정렬할 수 있습니다.
- **주소**(텍스트)를 `request-id-logs`로 정하면 글 경로는 `/posts/request-id-logs-<페이지 ID 앞 12자리>/`가 됩니다. 비워 두면 제목에서 경로를 만듭니다. 제목을 나중에 바꿀 글은 첫 발행 전에 주소를 정해 두세요.
- **프로젝트**(선택)에 프로젝트의 주소 값(예: `trace-note`)을 지정하면 해당 프로젝트의 관련 글에 연결됩니다.

**잠금 글**은 상태를 `발행 (비밀번호)`로 바꾸고 **글 비밀번호**(텍스트)를 입력합니다. 두 값이 맞지 않으면 빌드가 중단됩니다. 잠금 글의 요약·태그·카테고리는 공개되지 않습니다. 본문과 Notion에 업로드한 본문 이미지는 함께 암호화되며, 외부 이미지와 일반 첨부 링크의 접근 권한은 원본 서비스 설정을 따릅니다. 비밀번호 속성은 Notion 데이터베이스를 공유받은 사람이 볼 수 있습니다.

### 프로젝트

**제목**, **주제**, **요약**, **맡은 역할**을 채우고 본문에 배경, 작업 과정, 결과를 작성합니다. **주소**에는 `trace-note`처럼 영문 소문자와 숫자를 하이픈으로 연결한 고유 이름을 사용합니다. 이 예시의 상세 페이지는 `/projects/trace-note/`입니다. 주소를 비워 두면 페이지 ID를 사용합니다.

### 소개·수상·외부활동

[소개 원본](https://app.notion.com/p/4253839a3ab9816f87f0c8df7538851f)의 제목은 닉네임, **요약**은 한 줄 소개, 첫 번째 제목 2 앞의 본문은 인사말로 쓰입니다. **제목 2**를 추가하면 소개 페이지에 같은 이름의 섹션과 목차가 생깁니다.

- **수상 내역** 섹션은 수상 한 건을 글머리 기호 한 줄로 작성합니다. 홈에는 위에서 두 항목이 표시되므로 최근 수상을 맨 위에 추가하세요.
- **외부활동**은 행사명과 기간, 맡은 역할을 함께 적을 수 있습니다. 소속이나 경력도 같은 방식으로 섹션을 추가합니다.
- 소개 페이지의 프로젝트 목록은 공개 프로젝트에서 자동으로 구성됩니다.

## 자동 배포 설정

1. Notion에서 콘텐츠 읽기 권한이 있는 통합을 만들고 블로그 데이터베이스의 **연결** 메뉴에 추가합니다.
2. GitHub 저장소의 **Settings → Secrets and variables → Actions**에 아래 두 Repository secrets를 등록합니다.

   | 이름 | 값 |
   | --- | --- |
   | `NOTION_TOKEN` | 데이터베이스에 연결한 Notion 통합의 토큰 |
   | `DATABASE_ID` | 블로그 데이터 소스의 UUID. 데이터 소스가 하나인 데이터베이스는 데이터베이스 UUID도 사용 가능 |

   데이터베이스 링크에서 `?v=` 뒤의 값은 뷰 ID입니다. Notion 가져오기 단계에서 404가 발생하면 입력한 UUID와 통합의 데이터베이스 접근 권한을 확인하세요.

3. **Settings → Pages → Source**에서 **GitHub Actions**를 선택합니다. 첫 배포는 **Actions → Publish Notion and Jekyll → Run workflow**에서 실행할 수 있습니다.

[배포 워크플로](.github/workflows/notion-pages.yml)는 `main` 푸시, 수동 실행, 매시 7·22·37·52분의 예약 실행으로 시작됩니다. Notion만 수정한 경우 다음 예약 실행에서 변경 사항을 가져오며, GitHub의 실행 대기에 따라 반영이 늦어질 수 있습니다. 가져온 콘텐츠는 그 실행의 배포 결과물에 포함되고 저장소에 자동 커밋되지는 않습니다.

## 로컬 미리보기

Jekyll이 설치된 환경에서 저장소 루트에서 실행합니다.

```sh
jekyll serve
```

브라우저에서 [로컬 사이트](http://localhost:4000/)를 엽니다. 정적 파일만 만들 때는 `jekyll build`를 사용합니다. 로컬 Jekyll은 체크아웃에 있는 콘텐츠를 읽으므로 배포된 사이트와 글 목록이 다를 수 있습니다.

최신 Notion 콘텐츠까지 확인하려면 **별도 체크아웃**에서 아래 순서로 실행합니다. [가져오기 스크립트](_scripts/import_notion.py)가 소개와 프로젝트 사본을 다시 쓰므로, 실행 전에 해당 셸에 `NOTION_TOKEN`과 `DATABASE_ID`를 환경 변수로 설정하세요.

```sh
python3 -m venv /tmp/arecia-notion-venv
. /tmp/arecia-notion-venv/bin/activate
python3 -m pip install cryptography markdown-it-py Pygments
python3 _scripts/import_notion.py
jekyll serve
```
